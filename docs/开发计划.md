# 今天穿什么｜第一版开发计划

版本：v1.5  
日期：2026年10月27日  
状态：开发规划；UI 原型已获认可；RN 工程框架已初始化（2026-10-27），M0 剩余决策与业务实现未开始。

关联：[项目计划书](项目计划书.md) · [AGENTS.md](../AGENTS.md) · [功能索引](functions/README.md) · [原型基准说明](prototype/README.md)

## 1. 交付目标与计划边界

按照已认可的移动端原型，以 React Native + Expo + TypeScript 实现第一版 APP。保留简洁、大气的视觉方向，以及从一件衣服开始、按需补资料、局部调整、预览比较、保存复用的任务路径。

第一版最终目标是：用户用自己的衣服与个人参考完成一次真实搭配决策，并在实际穿着后记录感受。原生客户端的页面复现只是一个中间交付，不等同于完整产品上线。

本计划安排实施顺序、依赖、产物和验收，不替代功能文档。各功能的字段、补充频率和业务规则以其归属文档维护。工程框架已初始化，业务编码自 M1 起按阶段开展。

## 3. 原型落地时需要保留和替换的内容

### 保留

- 雾白背景、墨绿主色、柔和灰绿辅助色、大图与留白。
- “今天、衣橱、搭配、我的”四个主入口；搭配选择、局部调整与预览作为任务内页面。
- 统一的主操作按钮、单品卡片、锁定标识、场景摘要、底部弹层与轻量提示。
- 清楚区分收藏、穿过和实际满意，提供跳过与返回路径。

### 不能照搬原型实现

| 原型现状 | 正式实现要求 |
| --- | --- |
| 固定日期、天气、虚构头像与人物 | 来自真实用户选择和服务数据；未知保持未知，默认值明确可修改 |
| 内置演示衣橱及图片拼图 | 用户资料与演示资料隔离；每件真实衣服有独立资源、来源及状态 |
| 搭配板部分单品固定展示 | 画面、清单、锁定状态和预览必须共同引用当前方案版本，不能“换了清单没换图” |
| 预制两张模特图与定时器模拟生成 | 真正任务状态、模型结果与版本绑定；示例资源不进入用户真实结果 |
| 示例首次流程可以展示内置衣服 | 真实空衣橱不得悄悄混入演示单品；可在独立演示入口查看示例 |
| 浏览器本地存储与页面变量 | 原生本地数据库、持久文件与可恢复任务；演示资料单独隔离 |
| 桌面左右导航与设计说明 | 属于原型展示外框，不进入移动 APP |
| 浏览器缩放或图片展示 | 真机缩放、比较、触控目标、文字缩放与辅助功能单独实现和验证 |

原型不完整的异常和边界按功能文档补齐；不能以“原型没画”为由删去已经确认的规则。新的产品决定先更新归属文档及 AGENTS.md。

## 5. 技术落地原则

### 5.1 已确认方向

客户端采用 RN + Expo + TypeScript，使用 Development Build；允许关键能力原生扩展。以原型为视觉依据，不照搬浏览器 DOM、CSS 或原型中的全局状态。

分离设计组件、业务状态和数据访问：页面不直接耦合模型供应商，衣服卡片不各自发起识别调用。大量衣物列表使用虚拟化和合适尺寸的图片；高频手势避免繁重 JS 运算。

### 5.2 本地架构与待锁定方案

结构化资料使用本地数据库，原图、缩略图及生成结果保存在应用私有的持久文件目录；缓存可清理，不能充当唯一原件存储。优先评估 SQLite，具体库、加密方式与版本在 M1/M2 验证后锁定。数据库与文件通过稳定资源 ID 关联，不把临时相册 URI 当作永久资源。

取消此前的 NestJS、PostgreSQL、对象存储与 Redis 队列候选，不创建后端工程。任务记录持久化在本地，由可替换的执行适配层处理。AI 采用用户手动配置外部接口的方式，不内置模型或共享密钥。API Key 使用设备安全凭证存储，其他配置本地保存；接口兼容性与效果按实际配置验证。

天气联网可独立选择，手动场景始终可用；天气查询不需要传输人物或衣橱资料。外部 AI 调用已按默认允许执行；接入前确认传输范围、服务留存与凭证方案，不能在客户端内置共享供应商密钥，也不能以此默认新增自有服务器。

### 5.3 工程组织（已创建，2026-10-27）

```text
mobile/                    RN + Expo 客户端（@outfit/mobile，Expo SDK 58）
  index.ts → 已由 expo-router 入口取代
  src/app/                 expo-router 路由：四主入口 Tab（今天/衣橱/搭配/我的）
  src/ui/                  视觉令牌、通用原生组件与屏幕适配（已含响应式基础）
  src/features/            按功能组织的页面与交互（预留）
  src/domain/              单品、方案版本、任务等业务规则（预留）
  src/data/                本地数据库、文件与版本升级（预留）
  src/services/            相册、相机、任务等适配（预留）
packages/contract/         业务契约与共享校验（@outfit/contract，草案在 M3 前形成）
packages/experiments/      A 线 AI 实验脚本（Node 环境，经契约校验样本）
prototype/                 已认可原型，保留作为设计对照
```

包管理器已确定为 pnpm（workspace，`node-linker=hoisted` 兼容 Metro 与原生自动链接）。导航已采用 expo-router（2026-10-27），路由目录 `mobile/src/app/`，四主入口映射为 Tab 页。契约包供 APP 与实验脚本共用同一校验，当前仅版本占位，字段设计仍在 M3 实现前形成。

## 6. 数据流、接口与任务依赖

### 6.1 分层职责

| 层 | 主要职责 | 边界 |
| --- | --- | --- |
| 本地数据库 | 衣物、个人资料、方案版本、收藏反馈、草稿与任务记录 | 正式数据来源，应用升级不能清空重建 |
| 本地文件 | 原始证据、缩略图、结果图与删除生命周期 | 原件与可清理缓存分开，文件和记录保持一致 |
| 业务服务 | 候选筛选、方案修改、用途检查、版本校验 | 本地模块接口，不意味着 HTTP API 或服务器 |
| 执行适配层 | 解析、推荐、预览的执行与结果校验 | 调用用户配置的接口；提交按默认允许并限于任务所需 |
| 移动界面 | 编辑、状态说明、恢复与用户决策 | 页面关闭不能丢记录；任务继续执行需按平台验证 |

流程：用户选图 → 复制到本地持久目录 → 保存资料及来源 → 本地筛选与编辑 → 按确定路径执行 AI → 校验输入版本 → 结果保存在本地并供页面使用。

### 6.2 在联调前确定的接口契约

- 衣物档案：标识、属性来源和确认状态、图片引用、可用状态及版本。
- 个人参考：资料版本、适用用途、照片访问与删除边界。
- 搭配请求：锁定集合、当次场景、限制和偏好引用；返回真实单品引用、穿法、原因与缺口。
- 方案修改：父版本、变更项、锁定项、撤销关系；不能用旧结果覆盖新编辑。
- 异步任务：受理标识、状态、输入版本、结果引用、错误类别、允许的重试方式与幂等标识。
- 天气：地点、适用时间、来源、获取时间与失效标记。
- 收藏反馈：对应方案版本、是否穿过、满意度可未知、反馈上下文。

模型调用的付费重试、超时、重复回调、旧结果晚返回和断网恢复需有明确处理规则。初期可采用任务查询；通知与复杂实时通信不作为首版前置条件。

### 6.3 M3 之前建立、验收时冻结的业务契约

M3 开始实现交互前，先形成搭配请求、方案结果与方案修改契约草案；M3 通过条件必须包含契约 v1 已冻结。冻结对象是客户端与业务服务之间的稳定结构，不是模型原始输出，也不是禁止后续版本演进。

契约至少明确：锁定单品集合、场景和限制、具体单品引用、方案及父版本、穿法的适用部位与粒度、推荐原因、缺口与不可执行原因、可选字段的缺省语义、修改及撤销规则。未知值、空列表和失败不能混用。

交付物为版本化的契约文件、可执行校验及测试样例：正常组合、部分品类缺失、原因缺失、不支持某穿法、全部锁定产生冲突、过期版本和失败。测试数据必须通过与真实适配结果相同的校验；UI 不消费任意手写的 mock 形状。

职责：界面实现方和业务服务契约负责人共同确认；一人开发时也分别检查消费与提供两侧。AI 实验尽早提供真实返回样本和字段缺口；尚无真实样本不阻塞 M3，但明确记为“真实输出适配待验证”，不得据此宣称联调通过。

M5 中由客户端业务适配层把模型输出映射到业务契约，不能保证的原因或穿法要按已约定缺省、限制或失败表达，不编造。真实样本通过契约测试后才接入对应能力。若业务确实需要改变契约，记录变更原因、影响页面与状态、兼容方案及回归范围，升级版本并更新文档，不能为维持“冻结”而伪造数据。

### 6.4 本地资料生命周期与升级

M2 起即采用正式的本地数据模型与稳定 ID；M4 加固可靠性，不切换资料归属，不重新录入，不建设历史资料上传或同步机制。演示数据使用独立命名空间。

- 数据库有 schema 版本及升级步骤。保留 M2/M3 样本验证升级，升级失败保留原资料并可恢复，不以清库作为修复方式。“无云迁移”不代表无需本地数据库迁移。
- 文件写入、记录提交与任务结果采用可恢复流程，避免记录指向未保存文件；清理孤立资源前检查引用，不删除仍被方案或草稿引用的原件。
- 删除人物或衣物资料后停止新的输入读取；运行任务及历史衍生图按明确的删除范围处理，旧结果不能复活被删除档案。
- 检查系统自动备份、设备迁移与共享目录策略；用户资料默认排除系统云备份，并在目标平台验证配置。照片若原本来自系统相册，其既有同步由用户系统设置管理，APP 不承诺删除相册原件。
- 应用私有目录不等于已加密。M1/M2 确认敏感数据库和文件保护、密钥保存方式，M4 验证；日志不写照片、身体数据或凭证。
- 无云恢复：卸载、设备丢失或损坏可能导致资料丢失，产品需明确说明。手动导出/备份是否加入首版待确认，不自动新增备份平台或联网行为。

## 7. 分阶段实施与交付

以下是推荐顺序，不是已经执行的工作或工期承诺。工程框架初始化（2026-10-27）不计入任何里程碑完成；M0 中 RN/Expo 基础工程方式已随框架落地，其余决策仍待完成，各阶段验收状态均为“待开始”。

### M0：客户端开发启动基线

只完成开始 M1 必需的决定：近期验证平台与设备、原型与首版页面边界、RN/Expo 基础工程方式、演示与真实资料隔离、本地持久化与联网权限的基本约定。导航和必要库在 M1 验证后锁定，未用到的依赖不要求提前选齐。

交付物：简短启动决策记录、页面范围与原型差异清单、初步数据身份和版本约定，以及未决事项的负责人和影响范围。

通过条件：开发者可开始 M1，无需猜测目标环境、页面范围和基础边界。不要求 AI 执行路径选定或样本实验完成。不再以“M0 整体未完成”阻塞无关任务。

S0 服务端准备从计划中取消；本地存储选型与保护分别纳入 M1/M2，可靠性验证纳入 M4，不新增全局前置阶段。

2026-10-27 进展：平台与设备（Android 优先，真机 OPPO Find X9 Pro）、工程方式（Expo + pnpm workspace）与导航（expo-router）已决定并落地；页面范围与原型差异清单、数据身份约定记录仍待整理，M0 不视为整体完成。

### A：AI 可行性与试穿验证工作线（早启动，分批收口）

资料供 AI 使用已按 APP 默认允许，可直接用真实样本对接候选模型；试验参与者的素材用途与保存期限仍需明确同意。A 与 M0/M1 同期尽早启动准备，不属于 M0 完成条件。分别跟踪衣物理解、搭配推荐和上身预览，不能以某一项未完成阻塞全部客户端工作。

| 工作流 | 早期产出 | 直接影响的工作 |
| --- | --- | --- |
| A-衣物理解 | 可用字段、未知与误识别边界、真实样本与返回 | M5 自动解析接入；不阻塞手动入库及本地资料管理 |
| A-搭配推荐 | 真实单品约束可行性、原因和缺口样本、适配问题 | M5 推荐接入；向 M3 契约提供早期反馈 |
| A-上身预览 | 人物与衣服保真失败类型、可支持范围、耗时与成本 | M5 预览接入与该能力的验收 |

验证分两层：早期小样本确认“是否有可接入路径”，满足后可开始对应 M5 集成；集成后按功能文档完成真实性与决策价值验证，达标才放行对应能力进入 M6 内测范围。不能要求集成前完成全部产品验收，也不能只因接入成功就宣称真实性达标。

真人与实物的准备是长周期依赖：尽早落实参与者、衣物清单、拍摄与试穿时间、评价记录方法及资料使用同意。安排一次小规模完整试跑，发现流程成本后再扩大；不是等 M5 才约人试穿。

具体评价方法归属 [AI 上身预览](functions/AI上身预览.md)。固定可复用的参考与对照集用于模型迭代，只有输入条件明显改变或验证新问题时才组织补拍；保留未参与调参的验证组合，避免反复针对同一批样本调优后高估效果。

跟踪准备进度、可复用样本、待试穿任务、负责人及预计可用时间。真人预约或照片缺失只阻塞相应预览验证；M1–M4 中无关工作继续。若长时间无法获得有效证据，明确相关能力受阻，不用合成素材替代真实试穿验收。

### M1：客户端工程与设计系统

依赖：M0 的客户端启动基线。不等待 A 完成；必要组件在本阶段按平台兼容性验证和锁定。

工作：初始化 RN + Expo 工程、Development Build、类型检查、导航与安全区域；实现颜色、字体层级、间距、按钮、图片卡片、弹层、提示和空状态；将原型四个主入口和任务内页面映射到原生导航。

交付物：可在目标平台启动的工程、组件展示、基础页面、实际启动和构建说明。

通过条件：关键屏幕在目标尺寸可用；返回、键盘、长文本与文字缩放不会遮挡主操作；视觉经过原型对照。浏览器展示不能替代原生启动验收。

### M2：本地衣橱与任务式首次体验

依赖：M1。

工作：相机/相册、文件保存、轻量入库、详情与分类筛选、可恢复草稿；可跳过的偏好与当次场景编辑；明确真实空衣橱与演示入口隔离。阶段内尚无识别服务时允许手动确认，不能假装已经识别。

交付物：不依赖 AI 即可工作的个人衣橱基础版本及本地存储策略。

通过条件：拒绝权限可走替代路径；取消选图不丢草稿；重启后已录入资料可恢复；新增衣服不会自动混入示例组合；大量图片浏览及连续拍摄无已发现的阻断问题。

### M3：方案编辑与第一批收藏反馈

依赖：M2 与第 6.3 节业务契约草案；开发期使用符合契约的明确标注测试方案，不作为真实推荐发布。

工作：选基础单品、显示明确方案差异、锁定与局部替换、穿法和撤销、保存版本；第一批收藏、穿过记录、可选满意反馈及手动复用。

交付物：可完整走通“选择 → 调整 → 保存 → 记录 → 复用”的客户端版本，以及冻结的搭配请求/结果/修改契约 v1、校验与边界样例。

通过条件：第 6.3 节契约 v1 已冻结，测试方案通过共同校验，并登记真实模型适配的未决项；清单与图片引用一致；只替换未锁定项；无匹配时说明缺口；撤销可恢复上一版本；收藏不自动标记穿过；跳过满意反馈保留未知；个人偏好不会被当次要求覆盖。

### M4：本地数据可靠性与任务恢复

依赖：M2/M3 的数据模型、资料样本与任务契约。可提前设计；不依赖账号、服务器、天气供应商或 AI 效果验证。

工作：本地 schema 升级、文件与记录一致性、容量不足与写入失败处理、资源删除、敏感资料保护及系统备份排除；持久化任务状态、输入版本、取消与幂等；用可控执行器验证中断和恢复。

交付物：稳定的本地资料层、升级及恢复验证记录、任务执行接口；M2/M3 资料继续可用。

通过条件：第 6.4 节通过验证；升级失败不清库；写入中断不产生不可恢复的错误引用；删除后不再调用来源；重复提交不创建重复业务任务；APP 重启能恢复已保存状态，并将无法继续的任务明确标为中断/可重试。恢复记录不等于恢复计算进度，不承诺强制退出后继续生成。

### M5：真实推荐与 AI 预览闭环

依赖按能力放行：推荐接入需要 M3 冻结契约、M4 本地资料与任务能力及 A-搭配推荐早期结果；预览接入需要对应本地输入/任务能力及 A-上身预览早期可行性证据。衣物解析也在本阶段按 A 的对应证据接入，失败保留手动输入。用户配置功能及对应接口适配在接入前完成，资料使用权限已按 APP 默认允许；两项可分别启动和跟踪，不等待全部 AI 实验一起结束。M5 整体验收仍需本期承诺范围的推荐与预览均通过。

工作：实现用户手动模型配置与对应接口适配，再接入衣物解析与推荐；自动天气按可选联网方式接入，失败保留手动条件。结构化初筛、候选图片复核、真实方案生成；复用资料并执行按需补充；接入人物参考、所选单品与穿法；预览查询、失败恢复、比较与版本失效处理。

交付物：在已验证品类范围内，以真实输入完成的搭配与预览闭环，以及真实试穿对照记录。

通过条件：真实输出经适配层转换并通过与 M3 相同的契约校验，契约变更有版本及回归记录；只使用实际所选输入，不混演示图；用户离开页面不丢任务；改方案后旧结果不会覆盖新方案；数据不足不输出确定合身结论；视觉一致性及实际选择效果满足 A 工作线在正式验收前确定的评价口径。未经验证能力不可凭页面完成度进入上线范围。

### M6：真机质量验证与内测候选版

依赖：M2–M5 的相应目标功能完成。

工作：按页面和任务检查视觉一致性；中端设备图片性能、内存与手势；断网、取消、权限、后台、重启、重试、低存储空间和演示数据隔离；真人任务试用；检查日志中的敏感信息及资源删除；形成可分发的内测构建。

交付物：内测包、验证报告、已知问题、成本与等待时间观测、范围说明和下一批计划。

通过条件：核心流程无已知阻断缺陷；确认的体验与真实性标准有实际证据；未完成能力有明确限制且不误导；文档与实现同步。应用商店发布需再满足所选平台发布条件，不将内测包等同于已上架。

## 8. 里程碑与优先级

| 里程碑 | 可实际体验的结果 | 不能宣称 |
| --- | --- | --- |
| 客户端体验版：M1–M3 | 原生界面、自己的衣橱、方案编辑、基础收藏反馈 | 已接真实 AI 或真实天气 |
| 本地可靠版：M4 | 资料升级、文件保护与任务恢复 | AI 上身真实性已经达标 |
| 核心闭环版：M5 | 已验证范围内的真实推荐与预览 | 支持全部服装、精确物理试穿 |
| 第一版内测候选：M6 | 有完整验证记录的可分发版本 | 已完成商店发布与所有后续能力 |

优先级：先验证真实性风险和首次体验，再完成局部调整与数据恢复，然后扩展细节。动画精修不应早于锁定正确性、照片不丢与结果版本一致。

第二批反馈在首版基础可用后推进自然操作原因与预览问题反馈；第三批推进基于真实证据的场景复用和个性化。商品匹配保持后期，优先具体待购商品与已录入衣橱结合。

## 9. 跨阶段验收清单

### 9.1 产品与业务

- [ ] 不录完整衣橱即可开始；未知与缺失不会被解释成用户没有。
- [ ] 单品身份、属性来源与当前用途要求一致；不因无关缺失项阻断。
- [ ] 锁定、替换、撤销、穿法、预览引用共同遵循方案版本。
- [ ] 推荐结果只包含模式允许的真实单品；无可用候选时提供替代路径。
- [ ] 未反馈、收藏、穿过与实际满意分开；复用检查当前条件。

- [ ] M3 业务契约 v1 已冻结；正常与边界样例通过校验，真实适配未决项显式登记。
- [ ] M5 真实输出适配通过同一契约校验；破坏性变更有影响分析和回归。

### 9.2 移动体验与可靠性

- [ ] 原型核心视觉落实到原生组件，无桌面展示外框。
- [ ] 发布构建中检查衣橱快速滚动、详情返回、图片缩放与比较。
- [ ] 选图取消、权限拒绝、键盘遮挡、长文本和文字缩放有可用路径。
- [ ] 文件写入中断、切后台、重启与重复操作不会丢草稿或重复创建任务。
- [ ] 预览失败不影响已保存方案；旧请求晚返回不会覆盖新结果。

- [ ] M2/M3 资料经本地 schema 升级后仍完整可用，失败可恢复。
- [ ] 原件与缓存分开；系统云备份排除、删除范围和敏感信息保护有验证记录。
- [ ] AI 资料使用按 APP 默认允许落地，首次使用的告知与同意呈现经合规核验；断网仍可浏览、编辑、收藏及手动设置场景。

### 9.3 验证与交付记录

- [ ] 类型与业务规则检查、本地模块/任务联调、真机行为、真实试穿分别记录证据。
- [ ] 试穿样本与人员安排提前启动，评价方法在正式比较前确定；缺失反馈和未验证范围显式记录。
- [ ] 衣橱/方案的来源与版本、权限和删除行为经过验证。
- [ ] 首次满意方案的操作负担、实际采用情况、穿后满意及反馈覆盖率分别观察。
- [ ] 生成耗时、失败率和调用成本有测量记录；未反馈不计成功。
- [ ] AGENTS.md、功能文档、项目计划和实际实现状态一致。

不把每个静态展示组件都做成机械测试。自动化优先覆盖锁定与撤销、版本失效、事实不被推断覆盖、反馈未知状态、任务幂等及恢复等高价值规则。视觉与真实平台行为用相应验收补足。

## 10. 排期与资源安排

暂不指定发布日期：开发人数、首发平台、模型效果和服务条件尚未确定。M0 完成后即可估算并安排 M1–M3；M4 按本地数据与任务契约推进；A 分别给出早期接入与最终验收时间预期。试穿物流与模型试验单列，不要求整条工作线完成后才开始客户端排期。

估算时分别记录客户端、本地数据可靠性、AI 实验、联调与真机验证工作量，并注明设备与模型试验等待，以及外部服务选型与接入的等待。不能把等待时间当作可并行编码时间，也不能假设双平台无需分别验证。

最低职责覆盖：产品与设计验收、RN 客户端、本地数据与任务、AI 试验、真机测试。同一人可承担多项，但排期应按实际可用精力计算。

关键依赖按产出明确：

- M0 客户端基线 → M1 → M2 → M3；M3 开始前有契约草案，完成时冻结 v1。
- M2/M3 数据与任务契约 → M4 本地可靠性；天气按可选联网条件接入，手动输入不依赖服务。
- 确定的 AI 执行路径 + A-衣物理解早期结果 → M5 自动解析；不阻塞 M4。
- M3 契约 v1 + M4 本地资料与任务能力 + A-搭配推荐早期结果 → M5 推荐接入。
- M3 方案版本 + M4 本地输入/任务能力 + A-上身预览早期结果 → M5 预览接入。
- 相应真实适配、集成及试穿验收通过 → 对应能力进入 M6；M6 内测候选仍需所有本期承诺功能完成。

每个工作包登记负责人、产物、状态、阻塞对象和证据。状态区分未开始、进行中、通过、受阻；“M0/A 未完成”不能代替具体阻塞项。早期试验失败可以触发重选或收窄范围，不能把所有开发停在一个总关卡上。

## 11. 风险与决策点

| 风险 | 处理与决策点 |
| --- | --- |
| 预览无法保留人物或衣服 | A 提前小样本试验；早期可行性放行接入，集成后真实性放行验收，不用示例图冒充生产结果 |
| 录入负担高 | M2 首次任务试用；复用信息、按需补充，不通过伪造字段降低负担 |
| 跨平台库不能满足图片与后台体验 | M1/M2 真机验证，必要时原生扩展；不凭框架名称推断质量 |
| 用户配置接口的协议与能力不同 | 接入方式已确定；支持类型、模型标识和任务能力映射遇到具体接口时询问项目用户，不承诺任意 URL 兼容 |
| 默认允许与敏感个人信息单独同意要求冲突 | 以首次使用一次性告知与同意实现“默认允许、不逐次询问”；上线前按目标地区法规和应用商店审核核验呈现方式与范围 |
| M3 测试结构与 M5 真实返回漂移 | M3 开始前定草案、验收冻结业务契约；测试和真实适配共用校验；缺失按契约表达，变更升级版本并回归 |
| 本地升级、写入失败或设备丢失导致资料损失 | M2 建立正式模型，M4 验证升级与恢复；说明无云恢复边界，手动备份范围另行确认 |
| 系统备份或超范围传输违背本地隐私目标 | 验证用户资料的系统云备份排除；AI 传输限于任务所需输入，私有目录与加密分别验证 |
| 真人试穿物流与评价准备成为长周期瓶颈 | A 最早安排参与者、衣物和拍摄，先小规模试跑；复用对照资料并保留验证组合；只阻塞依赖的能力验收 |
| M0 被当成全局单点 | 缩为客户端启动基线，A 独立跟踪，按第 10 节具体产物放行 |
| 异步结果覆盖用户新编辑 | M3–M5 强制输入版本与任务关联，保留过期结果归属 |
| 原型误被当成完整产品规格 | 按本计划差异表补足；规则归属功能文档，新增决定同步记录 |
| 同时推进范围过大 | 以里程碑验收；第二、三批反馈和商品模块不挤入第一版 |

## 13. 暂不决定的事项与询问时点
