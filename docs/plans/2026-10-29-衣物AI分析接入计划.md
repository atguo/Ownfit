## 1. 摘要与授权边界

目标：利用用户在 APP 中配置的图片理解模型，分析已保存的衣服照片，提取可复用的数据，并在本地安全保存、展示和修正。

用户已确认触发方式：**新照片保存后自动分析；已有衣物手动补分析**。本轮仅将计划写入文档，不执行开发。本文件中的接口、表结构和参数是拟实施方案，不代表现有能力或已验证的模型效果；批准本计划后按这些默认实施。

本次包含：模型选择与缺配置提示、结构化分析、属性与任务持久化、版本保护、录入与详情接入、已有衣物批量补分析、删除联动和回归测试。

本次不包含：搭配推荐、上身预览、商品链接解析、多单品拆图、人物资料分析、自动天气、云同步、手动备份、AI 配置整体迁入数据库、完整后台调度或 M4 全项加固。不新增服务器、模型内置凭证或第三方依赖。

成功标准：现有照片无需重新上传；可用视觉模型能返回经校验的衣物档案；无模型或分析失败不丢照片；AI 不覆盖用户值；重启后状态和结果可查；重复提交与删除期间的晚返回不破坏资料。

## 3. 交互与数据流

### 3.1 新照片

1. 先复用现有流程保存照片副本与草稿；只有保存成功才考虑分析。
2. 为这次成功保存的草稿创建自动分析任务，批量选择只解析一次模型选择，每件衣物独立排队。
3. 没有符合条件的模型时，本批只提示一次“尚未配置图片理解模型”，提供“去配置”和“暂不分析”。不阻塞保存、不生成虚假的失败结果，也不在每次浏览时重复弹窗。
4. 多个候选且未设默认时提供模型选择，选定后将本批加入队列；跳过则保留未分析状态。
5. 分析完成后，草稿可预填建议名称和品类。只预填用户尚未操作的输入，不能覆盖仍未保存的编辑内容。
6. 用户仍需确认目标与品类才能入库；没有分析结果也可手动确认。非必填属性自动保存为 AI 推断，不要求逐项审核。
7. 去配置后返回原录入会话，重新检查模型并继续尚未提交的本批任务；退出会话后不暗中扫描或补发历史衣物，可用批量入口补分析。

### 3.2 已有衣物

- 详情提供“AI 分析”；有结果时显示“重新分析”，同时可查看最近任务状态和上次成功结果。
- 衣橱提供“分析未分析衣物（N 件）”：范围为有主图的草稿和已入库衣物，排除归档与删除记录。
- 批量入口只处理从未创建分析任务的衣物，跳过已有任务和成功结果；失败、中断、过期任务在详情显式重试，避免批量操作无提示地重复计费。
- 已归档衣物可查看历史结果，恢复到衣橱后再分析。
- 打开详情或切换筛选不触发新调用。批量显示已完成件数和各件状态，不生成虚构百分比。

### 3.3 结果展示与修正

详情展示简短描述、结构化属性、AI 来源、分析时间、所用模型和看不清之处。支持逐字段修改或确认；数组用现有表单组件编辑，枚举复用 Chip 按钮，不增加新 UI 框架。

已确认值展示为用户确认；有不同 AI 建议时作为附加建议展示，不自动替换。用户明确设置为未知也作为有效的人工决定保留。建议名称仅预填或作为建议展示，不在后台悄悄改写正式名称。

数据流固定为：

`本地照片与衣物 -> 模型路由 -> 持久化任务 -> 图片理解接口 -> 业务契约校验 -> 事务保存结果与属性 -> 页面读取`

页面不直接解析供应商原始响应，不把实验结果或演示数据当作真实结果。

## 4. 模型路由与接口

- 可选配置须满足 `urlKind = openai`、能力包含 `vision`、model ID 与基础地址有效，并能读取所需密钥。MiniMax 图像生成配置不属于衣物理解模型。
- 候选只有一个时直接使用；多个时优先使用记住的默认项，否则选择一次。默认项删除或不再可用时重新选择，不静默转发到另一家服务。
- 默认选择存本地任务设置表，只存配置 ID。原有 AI 配置 JSON 与 SecureStore 密钥存储不迁移。
- 文本连接测试通过不代表支持图片；不把 testStatus 作为视觉能力认证，也不要求每次分析前先付费测试。
- 排队时记录非敏感配置快照及配置内容指纹。发送前复核配置仍存在且未改变；若改变则进入 blocked 状态，用户重新选择后创建新尝试。指纹不包含连接测试时间等无关字段。
- 已发送的请求使用发送时快照，之后编辑或删除配置不改变该请求的目的地址；只影响未发送和后续任务。删除配置无法撤回已发送数据。
- 图片由 photoRepository 按主图 ID 读取应用持久副本，通过 OpenAI 兼容的 `image_url` 内容块发送内存中的 JPEG data URL，不把本地 file URI 当成远程可访问地址。
- 请求只含当前单品照片、必要品类提示和分析指令；不发送整库、其他衣物、偏好或人物资料。
- 分析调用默认 `max_tokens = 2048`、超时 90 秒、串行并发 1；这是开发初值，非服务保证。连接测试继续使用现有 16 token 和 30 秒默认。
- 不强制依赖供应商 JSON Schema 扩展；使用 JSON 提示词和客户端严格校验。允许去除围栏，拒绝多对象、截断、空回复和无效字段，不自动追加修复请求。
- 空回复即使 HTTP 200 也算分析失败。区分缺配置/密钥、鉴权、额度或限流、图片不支持、接口不兼容、网络/超时、输出无效、图片缺失和落盘失败。
- 错误仅保存白名单类别与脱敏摘要，不保存或展示供应商完整响应体、Authorization、图片 Base64、完整请求体或本地图片路径。

## 5. 版本化分析契约

在 contract 包新增独立 `GARMENT_ANALYSIS_VERSION = '1.0.0-draft'`，不改变既有搭配契约的含义。模型输出经适配器转换后通过同一校验器。移动端不直接依赖 experiments 包。

| 字段 | 结构与限制 |
| --- | --- |
| targetStatus | `single`、`ambiguous`、`not_garment`、`unreadable`，防止把多件衣服混为一件 |
| suggestedName | 可空、最长 30 字；不能覆盖用户名称 |
| category | 与当前衣橱大类对齐，另支持未知 |
| colors | 最多 4 个日常中文颜色名；非空时恰有一个主色 |
| pattern | 纯色、条纹、格纹、印花、拼接、其他；另有未知/不适用 |
| neckline | 无领/圆领、V领、立领、翻领、连帽、一字领、其他；另有未知/不适用 |
| sleeve | 无袖、短袖、七分袖、长袖、其他；另有未知/不适用 |
| fit | 修身、合体、宽松、oversize；表示外观版型，另有未知/不适用 |
| stylingTags | 最多 6 个风格或场景标签，每个最长 20 字，明确为 AI 推断 |
| description | 可空、最长 120 字，不允许以描述绕过事实边界 |
| unclearParts | 最多 6 项，每项最长 80 字，说明可见证据缺口 |

每个属性使用 `state = known | unknown | not_applicable` 与对应值；未知/不适用时值为 null。已知的空标签列表与未知分开，不用空字符串或 0 代替未知。不存模型自报的百分比置信度作为事实概率。

只有 `targetStatus = single` 才可产生可应用属性；其他情况保存诊断结果并提示补清晰单品照，不自动入库或拆图。描述和标签同样禁止猜测精确尺寸、面料成分、品牌、尺码、实际合身或确定保暖性能。

## 6. 存储与迁移方案

### 6.1 schema v3

沿用 M4 蓝图中的 `tasks` 名称，本次只支持 `kind = garment_analysis`；不同时建立另一张分析任务表或实现其他任务类型。

| 对象 | 计划变更 |
| --- | --- |
| items | 新增 `revision INTEGER NOT NULL DEFAULT 1`；用户修改、确认入库、归档/恢复、删除与更换照片时递增 |
| attributes | 保留现有字段；新增 `value_state`、`value_format`、`analysis_task_id`；新记录写入真实 item_version，AI source_type 为 ai_inferred |
| tasks | id、kind、item_id、status、input_revision、photo_id、input_key、request_key、attempt、config_id、config_snapshot、contract_version、prompt_version、result_json、error_kind、error_summary、created_at、started_at、finished_at、updated_at |
| ai_task_preferences | `kind` 主键与 `default_config_id`，只保存任务默认模型选择 |

`input_key` 由衣物 ID、revision、照片 ID、模型配置内容指纹、契约与提示词版本确定；`request_key` 标识一次主动提交，用唯一约束保证同次提交幂等。为同一衣物 queued/running 的任务建立唯一约束，阻止并行重复分析。

历史 attributes 的值不改写，value_format 默认 text；旧 value 为 null 时回填 unknown，否则 known。新数组存 JSON，标量存 text。不为旧数据补造来源、测量值或确认时间；已有名称按人工资料保护。

迁移以事务包住 schema 变更与 user_version 更新。支持空库、v1、v2 升级和重复打开；迁移失败回滚并保留原库，不删除数据库或重新生成密钥。任务服务在迁移成功后才能启动。

### 6.2 属性取值

- 属性保留历史证据，不覆盖旧行；用户修改/确认创建新的 confirmed 记录。
- 同一字段最新人工确认值优先，包含人工确认的未知。AI 类别建议不能直接改变 items.category。
- 没有人工确认值时，取当前照片最新可应用成功任务的属性。最新成功结果未知时显示未知，不回退旧推断冒充当前识别。
- 新任务失败不覆盖上次成功结果；页面同时标明“本次失败”与“上次成功时间”。
- 用户修改其他字段不删除已保存且照片仍有效的证据；用户修改与分析返回并发时按下面的提交规则处理，不通过全局更新时间猜测先后。

### 6.3 结果提交与删除

结果通过校验后，在短事务内重新读取衣物及任务，检查衣物未删除/归档、输入 revision 和主图 ID 一致、任务仍是本次 running 尝试。通过后同一事务写结果、属性及 succeeded 状态；AI 结果本身不递增输入 revision。

期间确认入库或修改资料导致 revision 不同的结果记为 stale，不自动应用；界面提示可重新分析。暂不做复杂的逐字段自动合并。已删除记录不保存任何晚返回的结果、错误正文或分析属性。

彻底删除在同一资料删除事务中清理该衣物 attributes 与 tasks，再沿用原有文件清理机制；保留现有最小 deleted 标记及收藏/穿着引用。删除、归档通知执行器尽力中止请求，但不承诺供应商取消或退款；即使中止失败也禁止结果落回当前档案。

## 7. 最小任务执行器

状态：`queued -> running -> succeeded | failed | interrupted | stale | cancelled`，另有发送前配置不可用的 `blocked`。未创建任务的衣物显示“未分析”。

- 模块级单例串行执行，由根布局初始化；React 重挂载不重复创建执行器。
- 任务创建和入队失败不回滚已保存衣物，明确提示“照片已保存，分析未开始”，允许稍后补分析。
- 不在数据库事务内等待网络。领取任务、结果提交分别使用短事务和条件更新，避免其他 UI 写入混入提交事务。
- 应用前台时领取 queued；切后台暂停领取新任务。正在发送的请求尽力完成，实际后台行为需真机验证，不承诺继续计算。
- 启动时将遗留 running 标记 interrupted，不自动重发；queued 只有在输入和配置仍有效且确认尚未发送时才可继续。
- running 在发送前持久化，极端中断可能把未真正发送的任务保守标为 interrupted；优先避免重复计费。
- blocked、failed、interrupted、stale 不自动重试。详情明确重试，建立新的 attempt/request_key，保留旧尝试关系与旧证据。
- 重新分析允许相同输入主动创建新尝试；重复点击返回已经存在的 queued/running 任务，不重复创建。
- 超时或连接断开可能已被供应商受理，显示“结果未知，重试可能再次计费”；客户端幂等不等于供应商计费幂等。
- 已拿到有效结果但数据库提交失败时，优先在当前进程中重试本地提交，不再调用模型；强杀后结果若未落盘则标中断，不宣称已经保存。
- 不提供进程外常驻服务、远端轮询恢复、系统通知或虚假进度。

计划内部接口：

- `resolveVisionConfig()`：返回可用配置、需选择、缺配置或配置无效的明确分支。
- `enqueueGarmentAnalysis({ itemId, configId, trigger, requestKey })`：创建或返回已有任务，trigger 区分自动、历史批量、手动和重试。
- `runGarmentAnalysis(input, signal)`：准备图片、调用接口、转换与校验，不直接修改页面状态。
- `commitGarmentAnalysis(taskId, result)`：按版本和删除规则原子保存。
- `getAnalysisView(itemId)`：返回最新任务、上次有效结果与人工优先属性，供列表/详情使用。

| 类别 | 必测情况 |
| --- | --- |
| 契约 | 正常单品、未知/不适用、空标签、无效枚举、超长字段、非衣物、多衣物歧义、围栏 JSON、空/截断/多对象响应 |
| 模型 | 无配置、仅文本/图像生成配置、多视觉配置、缺密钥、损坏配置、默认删除、排队期间配置改变、发送后配置改变 |

| 删除 | 排队/运行时归档或彻底删除、请求中止失败、结果提交与删除竞争、文件删除失败不复活资料 |
| 迁移 | 空库/v1/v2 到 v3、第二次打开、事务中途失败、旧属性格式、既有收藏/穿着引用完整 |

### 10.2 Find X9 Pro 真机验收

- 新增单张、多张照片：保存不等分析、一次配置提示、品类建议可确认、失败可手动入库。
- 对已录入照片执行批量补分析，不重新选图、不重复创建衣物。
- 逐件核对颜色、品类、图案与描述；错误能修正、未知不编造，不以 JSON 合法代替识别准确。
- 缺少视觉模型、密钥错误、不支持图片时提示清楚，并能进入配置后继续。
- 分析中编辑、确认入库、返回页面、归档、删除，验证版本和晚返回规则。
- 切后台、断网、强杀、重启，验证记录可恢复且不会自动重复计费。
- 重启后人工确认值和分析结果仍存在，收藏/穿着记录仍可使用。
- 验证系统字体放大、弹层滚动和键盘不遮挡新增操作。
