## M4 蓝图：本地数据可靠性与任务恢复（2026-10-29 方案存档，未排期落地）

> 目标：把 M2/M3 的数据层从"能用"升级为"可信赖"——升级可演练、损坏可防御、删除可复核、中断可表达；并为 M5 AI 任务交付执行接口。依赖仅 M2/M3，不依赖账号/服务器/天气/AI。

### 已就位（M2/M3 顺手完成，M4 只验证不重做）

- SQLCipher 加密 + 密钥入安全存储（已实测文件头非明文）
- 云备份排除（dataExtractionRules 不含用户数据目录，已核）
- 照片写入原子性（文件就绪才入库，失败清理）
- user_version 迁移框架（v1→v2 已自然发生）

### 工作块 1：升级演练与迁移加固

- 迁移测试台（dev 工具入口）：构造 v1 形状样本库（含草稿/入库/归档/照片/偏好各状态）→ 跑 v1→v2 迁移 → 逐项断言资料完整
- 失败注入：迁移中途模拟强杀 → 断言库可重新打开、重试迁移成功、任何情况下不清库
- 升级失败 UX：迁移抛错时 APP 进入"资料安全模式"（资料只读 + 明确提示 + 重试入口），不静默降级
- 交付：升级及恢复验证记录（写入文档）

### 工作块 2：一致性与容量防御

- 引用完整性扫描（dev 工具）：悬空照片引用、无记录孤儿文件清点
- 孤儿文件清理：只删"无任何记录引用"的文件（§6.4：清理前检查引用）
- 缩略图可重建：从原件再生成缩略图的入口（兑现"缓存可清理、不存唯一原件"）
- 写入前容量检查：可用空间低于阈值（50MB）时拒绝新照片写入并明确提示
- 写入原子性推广：审全部写路径（settings/config JSON 等）补齐失败处理

### 工作块 3：删除联动与敏感保护最终验证

- 删除单品 → 全库扫描确认无悬空引用 + 文件已删 + 无功能再读取
- 加密与备份排除的真机脚本化验证（文件头检查 + 系统备份行为）
- 日志红线检查：API Key、照片路径不入日志

### 工作块 4：任务执行接口（为 M5 打底；M4 只交付接口与骨架）

- schema v3：`tasks` 表（id / kind / status / payload / 输入版本引用 / idempotency_key / 心跳时间）
- 状态机：待处理 → 处理中 → 成功 | 失败 | **中断（可重试）**；取消语义定义
- TaskRunner 接口定义 + 骨架实现（**不接真实 AI**）；用一个假任务（延时器）验证"重启后未完成任务标为中断/可重试"的表达
- 边界：恢复记录 ≠ 恢复计算进度，不承诺强杀后继续生成

### 工作块 5：验证与交付

- M4 通过条件逐条真机验证（§7 M4 + §6.4 全项）
- 交付物：稳定的本地资料层、升级及恢复验证记录、任务执行接口；**M2/M3 资料继续可用**
- 文档同步：AGENTS §8、开发计划 §7 M4/§6.4 状态、mobile/AGENTS

### 登记的边界与未决项

- 手动导出/备份：M4 不做（2026-10-29 项目用户确认），M6 内测候选前决定

## 衣物 AI 分析接入（2026-10-29 实现完成，待真机验收）

> 定位：把 M4“工作块 4：任务执行接口”与 M5“衣物理解”的分析链路提前落地为可用骨架。**这不表示 M4 或 M5 完成**：M4 的升级演练、一致性与容量防御、删除联动真机复核等工作块未做；M5 的搭配推荐与上身预览接入未做。执行手册见 [衣物AI分析分批执行手册](plans/2026-10-29-衣物AI分析-分批执行手册.md)。

### 触发策略

- 新照片：草稿保存成功后自动按批入队分析，保存照片不等待 AI；一次选图只做一次模型选择/缺配置提示。
- 旧衣物：详情手动分析，或衣橱批量入口补分析（只处理 draft/active、有主图、从未创建过任务的衣物，不重跑失败/成功任务）。

### 已实现（P1–P7）

- 契约：`packages/contract/src/garmentAnalysis.ts`，独立版本 `1.0.0-draft`。9 个属性用 `Field<T>` 三态（known/unknown/not_applicable）+ `targetStatus`/`unclearParts`，严格对象拒绝未知键、非 single 时属性必须 unknown；`parseGarmentAnalysis` 校验。
- 存储：schema v3（`items.revision`；`attributes.value_state/value_format/analysis_task_id`；`tasks` 仅 kind=garment_analysis；`ai_task_preferences`）；迁移可测试、与 `user_version` 同事务、失败回滚不清库。
- 数据层：`taskRepository`（幂等/去重/条件状态更新/默认模型）、`attributeRepository`（人工优先取值、`getAnalysisView`、`commitGarmentAnalysis` 原子提交与 stale/discarded 保护）、`analysisTypes`（跨批类型）；删除衣物级联清理任务与属性且晚返回不复活。
- 模型接入（全部假网络）：`configStore` 增 `loadConfigsStructured` 与 `callRevision`；`visionConfig.resolveVisionConfig`（ready/choose/missing/invalid，默认失效不静默切换）；`garmentAnalysis`（提示词、单张 data URL、严格 JSON 解析、`鞋`→`鞋履`、2048/90000）；`openaiClient` 追加 `options{maxTokens,signal}`。
- 执行器：`services/ai/garmentTaskRunner.ts`（依赖注入、串行领取、发送前写 running、输入/配置版本校验、启动恢复、前后台门控、尽力中止、内存待提交重试）；`features/garmentAnalysisStore.ts`（单例、订阅、会话批次、requestKey）。
- 页面：`add.tsx`（保存后入队、缺模型提示、多模型选择、AI 建议预填不覆盖用户输入、隐私文案改正）；`wardrobe.tsx` + `WardrobeItemSheet.tsx`（批量入口、卡片状态、详情逐字段修正、明确确认入口与重试）；`_layout.tsx` 挂载执行器与启动恢复；`ai/config.tsx` 设默认模型。
- P7 缺口修复（2026-10-29，真机试用发现）：详情页原先只有“来自照片分析（未确认）”文案、无可见确认入口。已为每个未确认字段增加“确认”按钮，并在分析区顶部增加“确认全部分析结果（N 项）”；确认写入 `user_confirmed`、只落本机、不重新调用模型。

### 验证边界（不得误读）

- 自动检查：`pnpm typecheck`、`pnpm --filter @ownfit/contract test`、`node --test mobile/tests/*.test.cjs`（54 pass/0 fail）均通过。
- 真实模型调用：**0 次**。所有分析测试使用假 fetch；提示词与真实供应商输出（GLM/DeepSeek 等）的兼容性未验证。
- 真机：**未验收**。第 5 节真机清单（保存不阻塞、模型选择、详情修正、弱网/后台/强杀重启、归档删除联动、字体缩放与弹层滚动）全部标「待验收」。
