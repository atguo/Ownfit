## M4 蓝图：本地数据可靠性与任务恢复（2026-10-29 方案存档，未排期落地）

> 目标：把 M2/M3 的数据层从"能用"升级为"可信赖"——升级可演练、损坏可防御、删除可复核、中断可表达；并为 M5 AI 任务交付执行接口。依赖仅 M2/M3，不依赖账号/服务器/天气/AI。

### 已就位（M2/M3 顺手完成，M4 只验证不重做）

- SQLCipher 加密 + 密钥入安全存储（已实测文件头非明文）
- 云备份排除（dataExtractionRules 不含用户数据目录，已核）
- 照片写入原子性（文件就绪才入库，失败清理）
- user_version 迁移框架（v1→v2 已自然发生）

### 工作块 1：升级演练与迁移加固

- 迁移测试台（dev 工具入口）：构造 v1 形状样本库（含草稿/入库/归档/照片/偏好各状态）→ 跑 v1→v2 迁移 → 逐项断言资料完整
- 失败注入：迁移中途模拟强杀 → 断言库可重新打开、重试迁移成功、任何情况下不清库
- 升级失败 UX：迁移抛错时 APP 进入"资料安全模式"（资料只读 + 明确提示 + 重试入口），不静默降级
- 交付：升级及恢复验证记录（写入文档）

### 工作块 2：一致性与容量防御

- 引用完整性扫描（dev 工具）：悬空照片引用、无记录孤儿文件清点
- 孤儿文件清理：只删"无任何记录引用"的文件（§6.4：清理前检查引用）
- 缩略图可重建：从原件再生成缩略图的入口（兑现"缓存可清理、不存唯一原件"）
- 写入前容量检查：可用空间低于阈值（50MB）时拒绝新照片写入并明确提示
- 写入原子性推广：审全部写路径（settings/config JSON 等）补齐失败处理

### 工作块 3：删除联动与敏感保护最终验证

- 删除单品 → 全库扫描确认无悬空引用 + 文件已删 + 无功能再读取
- 加密与备份排除的真机脚本化验证（文件头检查 + 系统备份行为）
- 日志红线检查：API Key、照片路径不入日志

### 工作块 4：任务执行接口（为 M5 打底；M4 只交付接口与骨架）

- schema v3：`tasks` 表（id / kind / status / payload / 输入版本引用 / idempotency_key / 心跳时间）
- 状态机：待处理 → 处理中 → 成功 | 失败 | **中断（可重试）**；取消语义定义
- TaskRunner 接口定义 + 骨架实现（**不接真实 AI**）；用一个假任务（延时器）验证"重启后未完成任务标为中断/可重试"的表达
- 边界：恢复记录 ≠ 恢复计算进度，不承诺强杀后继续生成

### 工作块 5：验证与交付

- M4 通过条件逐条真机验证（§7 M4 + §6.4 全项）
- 交付物：稳定的本地资料层、升级及恢复验证记录、任务执行接口；**M2/M3 资料继续可用**
- 文档同步：AGENTS §8、开发计划 §7 M4/§6.4 状态、mobile/AGENTS

### 登记的边界与未决项

- 手动导出/备份：M4 不做（2026-10-29 项目用户确认），M6 内测候选前决定
- 无云恢复的用户告知文案：M4 拟稿，M6 上架前必须展示
- AI 任务的真实取消/超时/重试策略：M5 对接实际接口时确认
