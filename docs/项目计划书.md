# 今天穿什么｜项目计划书

版本：v0.12（产品规划草案）  
日期：2026年10月27日

## 1. 项目背景与目标

用户参考他人的穿搭购买衣服，但相同衣服在不同身材、外貌与发型的人身上效果不同；买回来后不适合自己，已有衣服也难以组合。

“今天穿什么”是一款面向移动设备的个人穿搭推荐 APP，通过真实衣橱、个人资料、天气与使用场景，为用户提出搭配，并利用 AI 展示本人上身预览。

核心目标是帮助用户选对穿搭。预览是否接近实际穿着、能否改善选择，是产品价值的关键；图片好看不能代替真实性。

目标用户是拥有一定数量衣服、需要日常搭配帮助，以及希望减少不合适购买的人。首批验证用户与服装品类待确认。

所有衣橱、人物照片、身体资料、方案、预览和反馈保存在设备本地，不建设云端资料库、账号系统或跨设备同步，以减少资料暴露与服务器开销。资料可提交 AI 服务用于解析、推荐与预览，使用 APP 即默认允许；用户自行配置模型 URL、URL 类型、API Key 和名称，APP 不内置 AI。无云恢复时，卸载或设备损坏可能造成资料丢失；本地保护与系统备份边界见开发计划。

## 2. 核心场景与整体流程

- 今天想穿某件已有衣服，希望知道其他单品怎么配。
- 根据明天的天气、通勤或活动安排选择穿搭。
- 从颜色、风格或参考图中的元素出发，寻找适合自己的方案。
- 衣橱不足时寻找相似商品，并在购买前后验证。
- 保存满意搭配，通过实际穿着逐步改善推荐。

整体流程：从想搭配的一件衣服开始 → 按需添加衣服与个人资料 → 结合天气与场景生成方案 → 局部调整 → 按需比较本人预览 → 实际穿着反馈 → 保存和复用。首次使用无需先录完整衣橱。

## 4. 阶段范围

| 阶段 | 目标与范围 | 阶段产出 |
| --- | --- | --- |
| 0：可行性验证 | 用少量已有衣服、固定组合和本人试穿，验证 AI 预览的实际决策价值 | 实验记录、误差清单、支持品类及能力边界 |
| 1：最小可用闭环 | 任务式轻量入库、个人资料、天气与场景、可局部调整的搭配、按需预览比较、第一批反馈与收藏复用 | 可完整使用的 MVP |
| 2：个性化优化 | 分批完善自然反馈与满意方案复用，验证个性化改善，逐步扩展起点和品类 | 经持续验证的体验改进 |
| 3：灵感与补购 | 优先待购商品与已录入衣橱匹配，再扩展概念搭配、自动找款及购买前后验证 | 从灵感到实物的完整流程 |

第一版重点是已有衣橱内的选择。商品匹配整体后期实现，不作为首个闭环的前提。反馈与复用分三批持续推进，具体范围由功能文档维护，不要求第一版完成全部个性化能力。

### 阶段编号如何对应

产品阶段与工程编号不是同一条串行时间轴：阶段 0 对应开发计划的 A 可行性/试穿验证工作线，可与基础开发重叠；阶段 1 由 M0 客户端准备及 M1–M6 实现验收支撑；阶段 2 对应后续第二、三批反馈与个性化；阶段 3 对应后期商品匹配。M0 不等于产品阶段 0。

详细映射与按产物放行的依赖统一见 [开发计划](开发计划.md) 第 8.1、10 节。AI 早期可行性放行对应接入，真实试穿验收决定相应能力是否进入内测，均不阻塞无关客户端工作。

## 5. 成功标准与主要约束

成功标准是用户根据推荐与预览选中的搭配，在真实穿着后仍然满意；同时，建立衣橱的工作量应可接受。

同时观察第一次获得满意方案的操作负担、方案是否实际穿着、穿后是否满意，并记录反馈覆盖情况；未知与未反馈不能算作满意。

主要约束包括预览真实性、录入负担、资料可靠性、生成速度与成本，以及人物照片的隐私管理。具体设计与验证方法归属各功能文档。

当预览改变人物体型或衣服细节，或者合身表现不足以支持判断时，应收窄能力承诺并继续验证，不能以图像美观代替产品目标。

## 6. 待确认事项与下一步

待确认：首批用户与品类、真实性最低要求、可接受的录入负担与生成等待时间、首发平台与支持系统版本、具体 AI 接口兼容范围、预算、人员和排期。

下一步完成客户端启动基线即可安排基础开发，同时尽早准备真实样本与试穿物流；本地数据可靠性和 AI 验证按对应能力推进，不等待全部实验完成才排客户端任务。成本评估区分设备容量与算力、开发成本，以及外部 AI 调用费用，不包含自建云端资料服务。

当前 UI 原型已获认可，第一版开发计划已形成，RN 工程框架已初始化（pnpm workspace，Expo）；业务功能未实现，也未进行模型实测、真实试穿验证或开发成本评估。功能文档中的设计规则不代表功能已实现。

除已确认的 AI 手动配置方式外，其余未决事项在开发遇到具体情况时询问项目用户，现在不做决定；触发时点见 [开发计划](开发计划.md) 第 13 节。
