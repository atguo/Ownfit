## 文档职责

项目计划书介绍项目背景、用户、价值、功能目标、整体流程和阶段范围。这里的功能文档说明具体设计、设计理由、数据与交互边界、异常处理及验收条件。

按可以独立讨论和验收的用户任务拆分功能，不按页面或按钮拆分。一个功能可以涉及多个页面；拍照、识别与补充尺寸作为衣橱入库的步骤共同维护。

## 统一内容结构

每份功能文档覆盖：功能目标与问题、范围与边界、使用场景与流程、关键设计与理由、数据与状态、异常与替代路径、功能依赖、验收条件与待确认事项。复杂功能可以在这些章节中增加表格、示例和子章节。

## 状态约定

- 已确定方向：当前讨论明确采用的产品原则和范围。
- 开发默认或建议：为了形成可执行方案采用的规则，不代表已有实测依据；调整需同步文档。
- 待验证或待确认：模型效果、阈值、外部服务和未决定的产品选择，不得描述为已经具备的能力。

## 维护规则

1. 每项详细规则只有一个归属文档，其他功能通过相对链接引用，避免复制完整规则。
2. 衣物资料与补全策略归衣橱；人物资料归个人资料；天气规则归天气；反馈交互与归因归反馈；图像生成和真实性实验归预览；筛选组合归搭配；商品匹配归补购。
3. 依赖文档只规定调用方需要什么，不重新定义提供方的字段、收集频率或异常策略。
4. 所有功能与架构变更须同次同步根目录 [AGENTS.md](../../AGENTS.md) 及归属功能文档，保持项目与入口约束一致。功能目标或阶段变化时同步项目计划书；功能列表、阶段或路径变化时同步本索引及相关引用。具体同步要求以 AGENTS.md 为准。
5. 保留来源、版本与未知状态；将规划、验证结果与实现状态分开记录。
6. 链接使用相对路径；移动或改名时更新所有引用。新增功能使用上述内容结构，验收项写成可观察的行为。


## 本轮确认范围（2026年10月26日）

七项产品建议已确认纳入设计。任务式首次体验、偏好分层、局部修改与撤销、预览比较及穿法控制、可修改天气场景写入对应功能文档。商品匹配保持后期实现；反馈与复用按三批推进。模型效果、交互参数与个性化收益仍需验证，确认设计方向不表示功能已实现。


## 开发计划评审补充（2026年10月26日）

M0 仅承担客户端启动基线，A 实验独立推进；取消 S0 与云端服务依赖，M4 验证本地数据升级、保护及任务恢复。所有功能资料仅本地持久化；资料供 AI 使用按 APP 默认允许（2026-10-26 确认），2026-10-27 确认由用户手动配置外部 AI，APP 不内置模型。搭配契约在 M3 冻结，试穿准备尽早启动；编号映射见开发计划。以上为设计约束，尚未实施或完成实验。

其余未决事项不在本轮决定。实施遇到具体情况时询问项目用户，按 [开发计划](../开发计划.md) 第 13 节推进；未经答复不将建议写成默认规则。
