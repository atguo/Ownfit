# AI 上身预览

版本：v0.5｜核心方案待实测｜2026年10月26日  
所属项目：[项目计划书](../项目计划书.md)

## 1. 功能目标与问题

利用 AI 展示本人穿着所选衣服的效果，帮助筛选真正适合的搭配。重点是本人和衣服是否被准确保留，以及预览能否改善实际选择，而不是单独追求图片美观。

## 2. 范围与边界

第一版从有限品类、少量已有衣服与固定拍摄条件开始验证。视觉搭配预览与长度、松紧等合身判断分别表达，图像逼真不代表尺寸或面料物理表现准确。

不承诺未经验证的精确物理试穿效果，也不输出无验证依据的“真实度 95%”。缺失资料或生成能力不足时收窄结论，不将虚构细节当成实物。

## 3. 使用场景与流程

用户选定搭配 → 检查单品图片与人物参考 → 复用资料并按需补充 → 组织当前套装输入 → 生成 → 检查人物与单品一致性 → 展示预览及能力限制 → 与实际试穿对照。

推荐与预览为独立步骤：不传整个衣橱，只传当前组合、必要细节、相关尺寸资料和人物参考。

## 4. 关键设计与理由

### 4.1 三类真实性

- 人物一致：保留体型、比例、脸部、肤色、发型，不擅自拉长腿或收腰。
- 衣服一致：保留颜色、图案、领口、袖型、长度与关键结构，不重新画一件类似衣服替代原物。
- 上身可信：对照衣长、袖长、腰线、松量、褶皱、厚薄和垂坠表现。

文字资料帮助检索；原图、细节和实测用于约束还原。输入尺寸不意味着模型必然按尺寸绘制，必须实验验证。

### 4.2 图片组织

对比多张独立图片、带单品编号的拼图、拼图加关键细节图。拼图只组织选定套装，保留各原图与编号映射；固定画布中单品越多，单品细节可能越少。不能假设一张图一定更便宜。

背面或局部图片仅在本次视角或关键结构需要时补充。输入数量、分辨率、延迟和成本依据具体模型测试确定。

### 4.3 为方案比较保持一致条件

已确认：预览围绕筛选设计。比较不同方案时，尽量使用同一个人物参考、身体比例、姿势、机位、光线、背景与展示尺度，减少非衣服因素影响选择。模型是否能稳定遵循这些条件需要实验，不能在验证前宣称已经保证。

同次比较记录公共条件及各方案版本。若条件明显不一致，提示比较限制或允许重试，不把人物被美化的一张图当作更优穿搭证据。

### 4.4 穿法控制与按需生成

将塞不塞衣角、外套敞开或扣上、袖口是否卷起等适用穿法作为方案内容，由用户确认或调整，并保存到方案版本中。模型不能在用户指定后任意改变；不适用的穿法不显示。

用户先看搭配组合，再选择需要的方案生成预览。无需等待所有候选完成图像生成才能继续；失败或未请求生成的方案仍可查看清单。局部修改后的图像必须关联新版本。

## 5. 数据与状态

输入引用搭配方案版本、每件衣物及图片版本、人物参考版本、必要尺寸与来源，以及生成视角。输出保存预览图、输入快照引用、任务状态、失败原因和限制说明。

任务区分待处理、处理中、成功、失败；图像生成成功与结果质量通过分别记录。结果展示哪些信息已知、哪些为推断、缺失会影响哪个判断。

人物或商品替换、尺寸修改时，旧图保留原版本归属，不能冒充基于最新资料生成的结果。

## 6. 异常与替代路径

缺必需图片时按衣橱统一策略补充，或换单品、保留搭配清单、稍后预览。人物资料不足可保留普通搭配，不伪造“本人”结果。

生成失败允许重试，已选搭配保持不变。发现人物被改变或衣服关键特征错位时标记不适合作为可靠结果；具体自动检查与人工确认方式待验证。

## 7. 功能依赖

[衣橱](衣橱资料入库与渐进完善.md)提供真实单品证据和补充策略；[个人资料](个人资料管理.md)提供人物参考；[搭配生成](基于已有衣橱生成搭配.md)提供已选方案；[商品匹配](灵感搭配与商品匹配.md)触发替换后重新预览；[反馈](穿着反馈与搭配收藏.md)保存实际试穿对照。

## 8. 验收条件与待确认事项

核心产品实验补充：让同一用户比较两套真实衣服的预览，记录其选择及原因，再实际试穿并记录最终偏好，观察预览选择与真实满意是否一致。保持比较条件尽量相同，记录偏差是否来自衣服、人物、姿态或画面美化。该实验检验决策价值，不仅是“图像是否像照片”。

### 8.1 行为验收

当前套装的输入可追溯；不读取无关整柜图片；单品编号映射正确；输入缺失不伪造证据；预览失败不删除方案；历史图能识别输入版本；没有依据不声称精准合身。

新增验收：比较方案可追溯公共条件；用户指定穿法保存并作为生成输入；明显偏离时不能标为可靠还原；未生成的方案不会阻断其他操作；替换单品或穿法后旧图不冒充新结果。

### 8.2 真实性实验

选少量已有衣服、固定组合，在相近姿态、机位与光线下比较 AI 图和本人实际试穿。记录错误类型、严重程度与输入方式，不能仅评价美观。

| 维度 | 检查问题 |
| --- | --- |
| 人物还原 | 身材比例、脸部、肤色或发型是否改变 |
| 单品还原 | 颜色、图案、领口、袖型或结构是否改变 |
| 上身表现 | 衣长、袖长、腰线、松紧是否接近实际 |
| 面料表现 | 垂坠、褶皱与厚薄是否误导 |
| 决策价值 | 根据预览选中的搭配，实际穿上是否仍满意 |
| 环境适配 | 结合反馈判断实际穿着是否过冷、过热或不适合活动；不单靠图片判定 |

人物或衣服被明显改变时先修正输入与生成方案；合身或面料效果不足时收窄能力承诺。是否扩大开发取决于实际决策价值。

待验证：模型供应商与输入限制、图片组织方式、可支持品类、准确性评价阈值、生成时间与费用。先完成样本和对照报告，再确定技术选型与规模化范围。

### 8.3 试穿方法与样本准备

试穿准备与客户端基础开发同期尽早开始，组织时间单独记录，不等到模型接入才约人。先用小批次完整试跑确认人员、衣物、拍摄、穿脱和记录负担，再确定正式验证范围和可接受标准；标准在正式比较前记录，不能看到结果后挑选通过口径。

- 明确参与者同意、素材用途与保存期限，记录单品、穿法、人物参考和拍摄条件版本。
- 分开测量外观还原、实际合身/舒适与穿搭偏好，不以偏好一致代替尺寸准确，也不要求用户必须在两套里选一个；允许都不喜欢、无明显偏好和无法判断。
- 记录先看预览时的选择，再记录实际穿着后的选择及原因；交替或平衡方案左右位置和试穿顺序，记录顺序以识别偏差。小样本结果只说明当前样本，不宣称覆盖所有人和衣服。
- 已有清晰对照图可复用于还原性迭代，减少反复穿脱；它不能取代新增的真实舒适度与偏好判断。资料条件变化时评估是否重拍。
- 调参样本与保留验证组合分开记录；同一套资料反复调优后的结果不能当作独立验证结果。
- 记录缺席、失败、未反馈和无法判断，不只保留成功图片。按品类报告支持边界、失败类型、耗时与调用成本。

早期实验只决定对应预览路径能否进入集成；集成后的正式验证决定能否进入内测范围。准备、早期接入和最终验收分别跟踪，任务依赖见 [开发计划](../开发计划.md) 的 A 工作线。真实试穿证据不足时保留受阻状态，不用生成素材替代。

## 本地资料与执行边界

人物参考、单品证据、任务记录及生成结果保存在设备本地，不建设预览服务器或云端图库。资料供 AI 使用按 APP 默认允许。APP 不内置模型，使用用户手动配置的外部接口；外部调用核验传输范围、留存、删除与凭证，不把本地存储宣传为照片绝不离机。应用退出后能恢复任务记录不等于计算可持续执行。

AI 接入方式见 [AI 模型配置与接入](AI模型配置与接入.md)。尚未确定的具体实施选择按 [开发计划](../开发计划.md) 第 13 节在实际遇到时询问项目用户，本轮不做决定。

开发待决约定（2026-10-27）：具体接口的查询、取消与结果未知处理，以及真实性失败标准、评价人员和样本要求，分别在接口验证和正式评价前询问项目用户；现在不设定默认策略或阈值。 统一询问约定见 [开发计划](../开发计划.md) 第 13 节。
