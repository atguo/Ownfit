## 批次

### 批 1：数据一致性能力（repository 层 + Node 回归）

- `maintenanceRepository`（新）：引用完整性扫描（悬空照片引用清点）、孤儿文件清点（photos/、thumbs/ 下无记录引用的文件）、孤儿清理（只删无任何记录引用者，§6.4 引用检查前置）、缩略图重建（从原件再生成）。
- Node 回归：内存文件系统 + 生产 schema 覆盖悬空引用、孤儿判定、清理不误删被引用文件、缩略图重建。

### 批 2：写入防御

- 写入前容量检查：可用空间 < 50MB 拒绝新照片写入并明确报错（photoRepository）。
- 写路径原子性审查：settings/config JSON 等其余写路径补齐失败清理，逐处登记。

### 批 3：开发工具入口（真机验证载体）

- "我的"页开发区新增"数据工具"页：一致性扫描、孤儿清理、缩略图重建、迁移演练（对拷贝库跑 runMigrations 并报告）、加密抽检（库文件头）。只读操作为主，清理需二次确认。

### 批 4：升级失败安全模式

- `db.ts` 迁移抛错时进入"资料安全模式"：明确提示 + 重试入口，不静默降级、不清库；App 其余功能明确降级表达。

### 批 5：真机验证与交付

- 通过条件逐条 adb 真机验证：升级演练（含中途强杀重启）、写入中断不产生不可恢复引用、删除后不再读取、重复提交幂等（已有）、重启恢复与中断表达（任务执行器已有，补真机强杀演练）。
- 无云恢复用户告知文案拟稿（M4 拟稿、M6 上架前展示）。
- 验证记录写入里程碑实施记录；AGENTS §8、开发计划 §7 M4/§6.4、mobile/AGENTS 同步。

## 边界

- 手动导出/备份：不做（2026-10-29 已确认，M6 前决定）。
- 恢复记录 ≠ 恢复计算进度；不承诺强杀后继续生成。
- AI 任务真实取消/超时/重试策略：M5 对接实际接口时确认。
- 不新增依赖；缩略图重建复用 expo-image-manipulator 既有用法。
