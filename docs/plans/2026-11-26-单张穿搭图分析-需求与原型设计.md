# 单张穿搭图分析｜需求、原型与实施验收

日期 2026-11-26

状态：已整理本次讨论与浏览器原型，待正式实施。本文记录需求和验收口径，实施排期与技术方案待定。

关联 [功能规格](../functions/灵感搭配与商品匹配.md) · [原型说明](../prototype/README.md) · [浏览器原型](../../prototype/inspiration.html)

## 1. 用户要解决的问题

在网上看到一张喜欢的穿搭图，分享给衣见，想知道换成自己、放到日常生活里，这套穿搭是否合适。适合或不适合都要有具体理由。用户只要能说「我喜欢这张图」，无需先解释自己喜欢什么风格。即使衣橱为空、手边没有类似衣服，也不方便拍个人照，仍然能看完一份针对这张图的分析。

这项功能服务于衣见核心链路的前两环：先理解用户想从参考图获得的效果，再把可用的搭配条件带回用户自己的穿衣选择。有相近衣物时，可以说明怎么借鉴；用户想添置时，可以说明优先考虑哪一件及原因。**实际试穿由用户自行决定，分析应在试穿前完整交付。**

首版范围是单张穿搭图的日常适配分析。既有「某件待购商品能否配进衣橱」是同一功能域内的另一条任务，沿用已有设计与阶段。商品搜索、自动选码、生成本人上身图和衣橱入库遵循各自的功能范围。

## 2. 产品流程

1. **接收一张图。** 从相册选截图，或用系统分享将图片交给衣见。保留分析对应的原图。替换图片后，图像依据和分析结论都要对应新图。
2. **直接给出首屏分析。** 用户无需先回答问题。说明整套哪些效果容易带回日常，哪些部分依赖拍摄或个人条件，再给出一个关键理由。条件不足时给出有条件的判断，比如「喜欢宽松叠穿时整套更合拍；偏爱轻便时可保留浅上深下，省去外层」。
3. **提供按需深入的路径。** 用户可核对原图、看分项依据，或选一个场景或穿衣习惯更新判断。一个问题只有在不同答案会实质改变结论时才值得提出。可以用简单选项或可跳过的穿法对照，允许「都喜欢」「暂时说不准」。对照图同时改变多个变量时，选择只说明本次更偏向哪张，无法据此归因到某个单项。
4. **按需解释怎么借鉴。** 当用户用文字描述已有单品时，围绕已知特征说明能复现哪些效果。资料不全时用条件表达。想添置时，只给一件优先考虑的单品，解释它为何比其他单品更能改变整体、要看哪些版型细节。获取穿着反馈属于后续验证，当前无需用户完成试搭、购买或记录。

## 3. 分析与证据规则

分析先核对图面和拍摄影响，再给出日常适配判断。界面可把结论放在最先阅读的位置，证据跟随结论呈现。

| 要判断的问题 | 依据与输出要求 |
| --- | --- |
| 图里实际看得见什么 | 找出对整体作用最大的一两个细节，例如敞开的门襟露出内搭和裤腰。能定位时标出图上位置。被挡住或裁切的部位标为看不清。 |
| 拍摄是否放大了效果 | 结合图上可见的姿态、步幅、视角、光线、构图等线索，指出**哪个效果**可能被放大，以及自然站立或日常走动时可能怎样变化。单张图无法确认的修图、实际身高、衣长等保留未知。 |
| 整套效果依赖什么条件 | 从版型、衣摆与裤腰的相对位置、松量、妆容或发型等实际相关因素出发，说明它们如何影响想保留的效果。例如束发让翻领更显眼。按影响取舍内容，避免逐项给没有证据的「门槛」。 |
| 换成用户是否合适 | 区分整套效果与仍可借鉴的局部。适用时说出适合、部分适合或不太适合及原因。引用已知的偏好、场景或衣物描述。个人条件未知时明确判断成立的条件。衣橱空只说明资料未知。 |

用户仅说「喜欢」时，衣见可以指出图上最突出的视觉效果，也可以给出可能的偏好解释。偏好解释保持为待确认，并允许用户直接说喜欢哪张或哪种效果。对一次选择的解释限于当次任务，长期偏好按现有个人资料规则维护。

## 4. 原型设计

从仓库根目录运行 `node prototype/server.cjs`，然后打开[交互原型](http://127.0.0.1:4173/inspiration.html)。代码入口见[页面](../../prototype/inspiration.html)和[交互逻辑](../../prototype/inspiration.js)。

### 页面结构

~~~text
窄屏
┌─────────────────────────────┐
│ 衣见             当前参考图   │
│                             │
│      大图居中，完整人物        │ 固定区
│                             │
│ 看图上细节          换一张图   │
├─────────────────────────────┤
│ 这套适合我吗？                │
│ 适配结论与关键理由             │
│ 拍摄影响                     │ 仅这一区滚动
│ 结合我的偏好      看完整分析   │
│ 有相近衣服？   想添一件？      │
└─────────────────────────────┘
宽屏左侧固定参考图与图像操作，右侧独立滚动分析。
~~~

- **参考图优先。** 手机窄屏原型在上方居中放大参考图，完整呈现示例中的人物。宽屏图片区在左栏。浏览判断、展开内容和补充偏好时，参考图保留在视口内。原型在 360 × 640 视口中参考图约高 275 px，具体原生尺寸需兼顾安全区、系统字体放大和分析空间。
- **用区块顺序体现重点。** 先读浅底的「适配结论与关键理由」，下一行单独看「拍摄影响」。完整分析按「为什么好看」「照片和日常的差别」「版型和比例」「妆容和发型的影响」分段，以间距和分隔线组织。原型窄屏结论标题 18 px，其余标题与正文保持接近。原生端按可读性与系统字体缩放确定字号。
- **操作入口清楚。** 图下保留「换一张图」「看图上细节」。点后者可开启原图标记，选择具体细节后显示对应文字。分析首屏保留「结合我的偏好」「看完整分析」。已有衣物和添置建议是独立的可展开内容。
- **两个案例覆盖不同判断。** 日常叠穿强调浅深分界可复用、外层是否保留看用户习惯。长外套街拍突出跨步、低机位和侧逆光对衣摆、比例的影响，选「喜欢轻便」后会出现「整套偏重，配色可以借鉴」。每个案例的结论、图上标记与分项依据都随图片一起切换。

### 原型迭代中的主要决定

| 反馈 | 当前处理 |
| --- | --- |
| 换图入口不明显，读分析时图片会离开视线 | 换图按钮移到参考图下，只有分析区域滚动。 |
| 信息平铺，第一眼看不出重点 | 结论与理由置顶，拍摄影响单列，细节按主题展开。字号保持为常规阅读层级。 |
| 主路径变成试穿，用户未必有合适的衣服 | 首屏直接交付分析，已有单品与购买意愿按需处理。 |
| 图片只占小角，无法边看边对照 | 窄屏上方改为居中大图，图像操作并排移到图下。 |
| 一张日常样图解释不了摄影放大效果 | 增加长外套街拍，与日常叠穿形成两个可切换的完整案例。 |

## 6. 验收用例

1. **只有一张自己的网图。** 衣橱为空、无个人照、无需预填偏好。通过分享和相册各走一次。结果能指出图上一处真实细节、它为何有效，以及回到日常有什么适配条件。用户能复述「我想借鉴什么」「适不适合我的哪个场景或习惯」「我可以怎么穿」。有明确适合判断时，用户能复述所用依据。
2. **图中关键证据被挡住。** 同一原图裁掉腰部或用遮挡盖住裤腰。模型应承认可见信息不足，改用仍看得见的依据，对原结论作相应调整。
3. **同图不同偏好。** 只改变一项输入，例如愿意扎上衣与不愿意扎上衣，或喜欢叠穿与偏爱轻便。照片观察应一致，适配判断与理由应正确改变。选择未知时仍能看完整分析。
4. **摆拍与自然站立对照。** 准备同一人同套衣服、条件可追溯的两张照片。先只看摆拍图并记录预计变化，再用自然站立照核对哪些效果保留、哪些减弱。模型评价依据应与可见证据一致。原型里的两套不同造型用于演示，正式验证使用同一套衣服的配对样本。
5. **完整图与分析可随时对照。** 在真机上滚动、展开细节、点图上标记、切换输入条件。参考图和换图入口能及时找到，图面与文字对应，操作后能看到更新的结论。
6. **按需提供已有衣物和添置建议。** 基础分析独立完成。对「我有一件较短的深色外套」给出基于已知特征的借鉴方法。用户主动展开购买建议时，可以看到一件优先单品、挑选细节和具体理由。
7. **切图和失败恢复。** 分析未完成时换入另一张图，旧结果不得覆盖新图。图片无法读取、供应商失败或分析信息不足时，页面保留当前参考图或给出明确错误及可用操作。

当前验证范围为浏览器原型。交付时分开记录原生入口验证、真实模型观察和适配质量、用户是否能据此做出穿衣选择三类证据。
