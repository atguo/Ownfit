## 1. 功能目标与问题

让用户通过自己配置的 AI 接口使用衣物解析、搭配推荐和上身预览，APP 不内置 AI 模型或统一供应商凭证，不建设自有 AI 中转服务器。

## 2. 已确认范围

用户手动填写以下配置，并保存在本机：

| 配置项 | 作用与边界 |
| --- | --- |
| 模型 URL | 用户指定的调用地址；填基础地址还是完整接口路径由 URL 类型决定（OpenAI 兼容填基础地址，MiniMax 图像填完整地址） |
| URL 类型 | 指定接口协议或适配类型；首批支持类型尚未决定，不承诺任意接口都兼容 |
| API Key | 用户提供的访问凭证；使用设备安全凭证存储，不写入普通数据库、日志或版本库 |
| 名称 | 用户填写的名称；是展示名称还是兼作请求中的模型标识，实施时确认，不自行等同 |

用户提供自己的服务凭证，APP 不提供内置调用额度。实际费用与额度由所配置服务及其账号规则决定，不在此预设 APP 付费方案。

资料以本地为正式存储来源，调用时只将任务必需输入发送到配置接口，结果保存回本地。APP 默认允许 AI 任务使用相关资料，不逐次询问；外部服务留存不能由本地保存策略保证，不宣传所有照片绝不离机。

## 3. 使用流程与设计理由

填写接口配置 → 本地保存 → 通过对应适配器调用 → 校验业务结果 → 本地保存结果并展示。配置成功、接口可访问与模型具备某项业务能力是不同状态，不能混为一谈。

解析、推荐、预览消费统一的业务契约，不直接依赖某个供应商返回格式。接口可生成文字不代表支持图片输入或上身预览；不能调用时保留已录入资料与已选方案，不用演示结果冒充真实结果。未配置时仍可使用本地资料管理。

## 4. 数据与状态

2026-11-03 补充设计方向：预览生成能力与生成后视觉核对能力分别解析。生成器仅支持衣物文字时仍可使用文字路径；可用视觉配置负责核对本次原图与生成图，无视觉能力时明确“未自动核对”。优先复用用户已选配置，失效时不静默切换供应商，不要求逐任务重填配置。具体核对路由与受控重试预算待实施确定，尚未接入；规则归属[AI 上身预览](AI上身预览.md)。

非敏感配置与密钥引用存本地，API Key 单独存储。任务关联所用配置及输入版本；运行中切换或删除配置时如何处理，待具体实现时询问项目用户，不悄悄将旧任务发送到新地址。

## 5. 异常与能力边界

需区分未配置、鉴权失败、接口不兼容、不支持当前任务、额度不足、网络失败及结果无效。同步调用、异步查询、取消与幂等能力以实际接口为准，不保证所有接口都可恢复计算，也不自动将结果未知的请求按失败重发。

具体错误呈现、连接测试方式、重试与恢复策略在遇到对应接口时询问项目用户后确定。

## 6. 功能依赖

为 [衣橱](衣橱资料入库与渐进完善.md)、[搭配生成](基于已有衣橱生成搭配.md) 和 [AI 预览](AI上身预览.md) 提供配置与接口适配。执行阶段及待决问题见 [开发计划](../开发计划.md) 第 13 节。

## 7. 验收与待确认事项

已确定的验收边界：无内置模型或共享密钥；上述四项可手动配置；密钥不进入普通资料与日志；只调用用户配置的接口；接口失败不丢本地资料；真实输出通过业务契约校验。

暂不决定：配置入口布局、URL 类型清单、地址拼接规则、名称与 model ID 的关系、单配置或多配置、不同任务如何选择模型、连接测试、密钥更新删除、运行中配置变更，以及各接口恢复能力。开发遇到具体情况时向项目用户提出可评估方案，取得答复后再实施相关部分，不提前写成默认行为。

已决定（2026-10-27，项目用户确认；配置管理提前落地，任务执行接入仍属 M5）：

- **URL 类型首批清单**：OpenAI 兼容（基础地址拼接 `/chat/completions`）与 MiniMax 图像（完整接口地址）。依据 A 线现实：项目用户在用服务（GLM/DeepSeek/MiniMax）恰好覆盖这两种协议；新协议出现时再扩充清单。
- **地址拼接规则（2026-11-03 项目用户确认调整，取代 10-27 的"一律自动拼接"）**：OpenAI 兼容 = 基础地址填到版本号为止（如 `https://api.openai.com/v1`），自动拼接 `/chat/completions`；**MiniMax 图像 = 用户输入完整 API 地址**（如 `https://api.minimax.cn/v1/image_generation`），调用时不追加任何路径——不同图像服务的接口路径可能完全不同，自动补路径会把 `/v1` 基础地址拼成 `/v1/v1/image_generation`（真机 404 实证）。表单按类型分别提示填写方式。
- **服务地址仅接受 https（2026-11-03 项目用户确认，M6 批次 2；2026-11-04 落地）**：内测包禁明文——`app.json` 移除 `usesCleartextTraffic`（Android 默认禁明文，prebuild 产物已核验），配置表单保存/测试前经 `insecureUrlProblem` 拒绝 `http://` 地址。自部署模型需启用 https（或经反向代理）；收敛前保存的 http 配置调用时会被系统拦截，需重新编辑。
- **名称与 model ID**：分开两个字段——名称为展示名，模型 ID 为请求参数。
- **多配置**：配置为列表，每条带能力标签（文本/视觉理解/图像生成）。“不同任务如何选择模型”以能力标签实现最小路由（任务按所需能力选配置），细粒度策略待 M5 任务接入时确认。
- **配置入口**：APP“我的”页 → 模型配置（列表 + 表单，见 `mobile/src/app/ai/`）。
- **连接测试**：OpenAI 兼容 = 一次极小文本请求（max_tokens 16）；MiniMax 图像 = 实际生成一张 512px 测试图（表单明示会产生费用）。测试结果与“未测试/通过/失败”状态分开展示——配置成功不等于接口可用。
- **密钥存储与更新删除**：API Key 存设备安全存储（expo-secure-store），配置文件只存引用；编辑时可覆盖 Key；删除配置需二次确认并级联删除 Key。
- **仍待确认**：运行中配置变更对进行中任务的处理（M5 任务接入时确认）；各接口的查询、取消、超时与重试策略（对接实际接口时确认）。

已决定（2026-10-29，项目用户确认；**仅覆盖衣物分析任务**，推荐与预览接入时如无新决定则沿用）：

- **视觉模型路由（D1）**：候选须满足 URL 类型=OpenAI 兼容、能力含"视觉理解"、模型 ID 非空、基础地址有效、且能读到 API Key；MiniMax 图像配置不参与分析。只有一个候选时直接使用；多个候选由用户选择。选择结果按任务类型记入本地 `ai_task_preferences`（只存配置 ID）。**已记录的默认失效时，即使只剩一个候选也要求用户确认新模型，不静默切换供应商。**
- **缺配置与失效的区分**：没有任何视觉候选 = 未配置；有视觉候选但缺可读 Key，或地址/模型 ID 无效 = 配置无效；配置文件损坏无法读取 = 读取失败。三者分别提示，不统一归为"未配置"。
- **配置版本与快照（D2）**：`ModelConfig` 增加 `callRevision`（旧配置缺省 `legacy`）。URL 类型、基础地址、模型 ID、能力标签或 API Key 变化时生成新版本；**名称与连接测试结果变化不更新**。排队时固定配置快照（只含 id/名称/URL 类型/基础地址/模型 ID，绝不含 Key）；发送前比对当前 `callRevision`，不同或配置已删除则任务进入 blocked，不把请求改发到新地址；已发送的请求沿用发送时快照。
- **分析调用参数与恢复（D3）**：衣物分析 `max_tokens=2048`、`timeoutMs=90000`、并发 1；连接测试保持 16/30000。不自动重试可能已计费的失败；超时/中断后由用户手动重试，重试产生新任务并保留 `retry_of_task_id`。客户端取消只是尽力停止，不保证供应商停止执行或退款；超时或连接中断时结果未知，界面须提示"重试可能再次计费"。
- **输出解析**：只接受完整 JSON 对象，或整体包在一层 ```json 围栏中的对象；不截取首尾花括号"修复"任意文本，不追加一次模型调用修 JSON；HTTP 200 但内容为空按分析失败处理（连接测试仍按"连接可达"处理）。
