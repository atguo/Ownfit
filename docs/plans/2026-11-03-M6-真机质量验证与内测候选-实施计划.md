## 目标与边界

目标：形成有完整验证记录、可分发的 Android 内测包，附验证报告、已知问题清单、成本与等待观测、范围说明。

不能宣称：已完成商店发布与上架；已完成后续能力（反馈第二/三批、商品匹配）；Development Build 等于内测候选。

放行说明：M6 前置是"M2–M5 相应目标功能完成"。M5 已视同验收，其登记的实现缺口（代码类）作为本计划批次 1 先行收尾，不重复走独立验收。

## 批次 4：真机质量验证（Find X9 Pro，部分项目用户参与）

按开发计划 M6 工作清单执行，逐项记录通过/失败/未测：

- 视觉一致性：按页面与任务对照原型，含字体缩放、安全区域、键盘。
- 性能与内存：衣橱大量图片滚动与详情返回、预览图加载、滚动位置稳定。Find X9 Pro 为高端机，中端机结论不得由其代替（缺项如实登记）。
- 异常路径：断网、取消、权限拒绝、切后台与重启恢复、重试、低存储、演示数据隔离。
- 安全与资源：日志不含 API Key/密钥等敏感信息；删除后文件清理；系统云备份排除复核。
- 真人任务试用：项目用户按真实任务走完录入 → 推荐 → 预览 → 反馈，结论入报告。

## 批次 5：内测交付物与收口

- 验证报告：批次 4 逐项结果 + A 线效果证据补记（识别质量核对、推荐 review 回填、试穿对照结论，项目用户参与）。
- 已知问题清单、范围说明（未完成能力写明限制，不误导）、成本与等待观测。
- 下一批计划意向（反馈第二批等），不预先承诺。
- 文档同步：AGENTS.md、里程碑记录、开发计划、功能索引。

## 通过条件

核心流程无已知阻断缺陷；确认的体验与真实性标准有实际证据；未完成能力有明确限制且不误导；文档与实现同步。应用商店发布需另满足所选平台条件，不将内测包等同上架。
