## 1. 结论

**主链路已有实现，但不能认定所有计划都已完整落地。最新能力改进批次仍有代码缺陷，M6 也尚未收口。** M0–M5 的既有用户验收结论保留；本次发现的缺口作为当前版本待办，不追溯撤销历史验收。

本次服务核心四环：检查衣物证据是否可信传递、推荐是否保住真实单品与用户约束、预览是否确实核对且可公平比较、反馈是否可靠保存复用。发布与存储检查支撑这条链路在设备上稳定可用。评价依据是实际调用链、生产模块的无网络复现和既有验收记录，不用模块数量或测试通过率换算产品完成百分比。

三层结论：

1. **工程与行为**：本地衣橱、动态分析、手动搭配、三类任务、反馈和配置持久化已有基础；最新预览核对正常路径不通，推荐输入身份、天气竞态、预览穿法版本及发布签名仍有实质问题。
2. **模型表现**：已有历史真实调用记录；最新防偏、局部推荐和同条件比较的效果未知，本次真实模型调用 0 次。
3. **实际选择价值与负担**：未知；固定任务对照、实际试穿、主动操作量、等待与成本仍需证据。现状不足以放行 M6 内测候选。

## 3. 当前版本需要优先处理的代码问题

P1：影响核心约束、关键能力或内测交付，应先收尾。P2：功能语义/可靠性差异，应在对应能力放行前解决。本表不是未测设备清单，均有当前代码依据。

### F1 · P1：自动防偏核对未拿到生成结果图，C8 正常链路不通

- 依据：`mobile/src/services/ai/previewTaskRunner.ts:332` 保存结果后忽略返回路径，`:352` 把领取时的 `task` 传给核对；`mobile/src/features/previewStore.ts:195` 只按该对象的 `resultPreviewPath` 读取图；runner `:409` 遇到空图直接登记 unknown。
- 无网络复现：数据库替身保存路径为 `previews/new.jpg`，传给 `loadCheckImages` 的路径仍为 null，视觉调用次数为 0，最终核对为 unknown。正常新任务的路径原本就是 null。
- 影响：用户配置视觉模型也不能获得承诺的自动核对/纠偏；这是实现断点，不是模型效果未知。
- 修复验收：使用已提交的结果版本/路径启动核对，纠偏后核对新图；用生产 store/runner 联动覆盖 ready、missing、核对失败和一次纠偏。仅重试下载成功后也需明确进入核对或显示未核对。

### F2 · P1：推荐仍用可漂移别名恢复锁定项，旧 R4 未修复

- 依据：`mobile/src/features/recommendationStore.ts:103` 按执行时 active 衣橱重新解释 `item-N`；`:245` 只保存 scene/lockedAliases/body/preferences/note，未保存真实 ID 映射及衣物版本。指纹仍使用别名集合。`recommendationTaskRunner.ts:186` 还会过滤不存在的锁定别名。
- 无网络复现：衣橱 A/B/C 时 `item-2` 为 B；归档 A 后，同一锁定别名变成 C。
- 影响：等待中的请求可能锁错衣物，等数量换衣物/改属性也不能可靠区分输入；违反“只用实际所选衣物”。
- 修复验收：持久化真实 ID、别名映射及版本/快照；执行和采用时按原请求复核，不静默舍弃锁定。覆盖队列期间新增、归档、删除和改属性。

### F3 · P1：逐件穿法未进入预览指纹和“本方案”判断

- 依据：`previewRepository.ts:250` 的 `buildPreviewInputKey` 与 `:272` 的 `previewInputMatches` 均无 itemWear，虽然 `:364` 把它写入 input_json；`PreviewSheet.tsx:141` 加载当前输入也只有 itemIds/wearStyle。
- 无网络复现：只将外套从自然垂放改为敞开，其他输入不变，两次指纹完全相同。
- 影响：在途新请求可能被合并到旧穿法任务，旧图仍标“本方案”；C4 的落库/提示词完成不能代替 C2 版本闭环。
- 修复验收：逐件穿法规范化后参与去重、快照、显示匹配；主穿法与逐件覆盖规则一致。新增“内搭不变、仅改外套穿法”的回归。

### F4 · P1：天气异步写回未核对最新日期，旧 R6 只修了一部分

- 依据：`mobile/src/features/weatherAuto.ts:54` 取 previous，`:64` 检查旧 day，`:102` 请求完成后直接写回；定位失败 `:57` 原样返回，已过期 real 温度也可能保留。推荐 `loadSceneSnapshot` 只检查 tempSource，不重新核对时效。
- 无网络复现：今天开始查询，等待响应时改为明天；响应后 day 保持明天、tempSource 却成为 real，温度来自今日请求。
- 影响：当次场景和真实天气不一致，会影响外套/鞋履选择；现有 R6 测试只覆盖请求开始前已是明天等场景。
- 修复验收：地点/日期/请求版本绑定，写回前复核；定位失败及长期前台停留导致的过期数据在消费前失效。

### F5 · P1：正式签名 properties 的路径解析错误

- 依据：`mobile/plugins/withReleaseSigning.js:10` 为 `../../keystores/keystore.properties`，`:21` 却由 `rootProject.file` 解析；Android 根工程是 `mobile/android`。
- 路径复现：解析得到 `D:/workspace/Ownfit/keystores/keystore.properties`，而说明要求放在 `D:/workspace/Ownfit/mobile/keystores/keystore.properties`。缺文件会按 `:22` 回退 debug 签名。
- 影响：用户严格按现有说明生成签名材料，release 仍可能使用 debug 签名；“插件注入成功”不能证明正式签名生效。
- 修复验收：路径与说明一致；正式分发构建缺签名时应明确阻止或强制检测；以 APK 实际证书验签和覆盖安装验证收口。本轮未读取任何签名密码。

### F6 · P2：预览迟到结果仍可写入，旧 R8 只在推荐侧部分落实

- 依据：`previewRepository.ts:457` 和 `:474` 的结果/待下载 UPDATE 只有任务 ID 条件，没有允许状态或执行版本。runner 先保存结果再单独置 succeeded；看门狗仅阻止后一个状态更新，挡不住前一个结果写入。
- 触发：任务已 interrupted/cancelled，迟到的生成/下载仍返回，result_json 仍可改变；仅重试下载也是先写结果、后做条件状态更新。
- 修复验收：结果引用与终态有一致的条件提交；不接受迟到执行者写入。文件失败清理与异步核对/纠偏应纳入任务生命周期，不能把生成 succeeded 当作所有后续操作已结束。

### F7 · P2：“同条件比较”只验证人物参考版本

- 依据：`previewRepository.ts:549` 的 `createPreviewComparison` 只检查成功、路径存在于记录和参考版本相同，不比较 configId/configRevision/生成参数；`PreviewSheet.tsx:314` 却声明两次使用相同生成参数。
- 无网络复现：相同参考、不同模型配置的两任务仍可创建比较组。
- 影响：模型或条件差异可能被误当成搭配本身差异，损害预览辅助选择的价值。
- 修复验收：持久化并核对实际共同条件；无法保证时明确作为非同条件历史对照；比较结果绑定稳定图像版本，重大偏离图的用途限制与功能文档一致。

### F8 · P2：局部推荐只有“其他 ID 必须出现”，没有完整限定可变范围

- 依据：`mobile/src/app/outfit.tsx:117` 的 aiSwapSlot 将其他件作为锁定 ID，目标槽位只写进 note；归一化只验证包含锁定项。`RecommendationSheet.tsx:198` 采用整套候选并使用 candidate.wearStyle，没有传原 slotWear，亦未对新增非目标槽位做拒绝。
- 触发：只换鞋时模型保留原上装/下装但增加外套、改变主穿法，候选仍可接受；采用时既有外套逐件穿法会被默认空映射替代。当前采用的 keptLocks 只是与此刻 session 取交集，不是完整复核原请求锁定。
- 影响：B5“其他件不变”的 UI 承诺超出本地校验保证；R3 不能判定完全收口。
- 修复验收：持久化基线/允许变化槽位和穿法，候选及采用两处校验；只替换目标槽位并保留其他穿法、锁定和撤销语义。

## 5. 既有工程缺口及范围边界

- **预览文件可靠性仍待处理**：人物参考先删旧文件再 move（`previewRepository.ts:94`）；失败可能损失旧参考。维护仅扫描 photos/thumbs，不覆盖 previews/preview-ref。纠偏结果替换、删除记录与文件失败的恢复也不能由现有照片维护测试证明。

5. 明日自动预报仍不新增；沿用手动输入降级。长期前台停留也在展示/推荐前检查有效期，不只依赖 AppState 刷新。

**回归**：使用可控 Promise 与时钟，覆盖请求中切明天/改城/手动温度、午夜跨日、定位失败且旧 real 过期、旧请求最后返回、多个请求共用/换目标、入队后次日执行。人工确认值不能被迟到自动结果覆盖。

### 8.7 F5：修正正式签名路径，并让分发构建明确失败

**改动位置**：`mobile/plugins/withReleaseSigning.js`、`mobile/keystores/README.md`；原生目录由 prebuild 生成。

1. properties 改为相对 Android rootProject 的 `../keystores/keystore.properties`，或由插件生成明确等价路径；测试断言最终解析到 mobile/keystores，不能只计数注入标记。

3. 插件测试覆盖正确路径、二次运行幂等、旧注入块升级、模板不匹配和缺签名；构建验证同时包含 debug 不受影响及 release 缺材料失败。

### 8.9 数据升级、旧资料和失败恢复

- 推荐/预览的输入 DTO 使用各自版本，写在现有 input_json；改变内部输入不自动要求修改公共 Plan 1.1.0。只有公开业务字段变化才升级契约并补样例。

- 运行失败优先保留旧有效结果及明确状态。不得删除库、重置资料或回退 schema 来“恢复”；版本回退仅限确认可读新 schema 的构建，否则通过前向修复。禁止为了满足测试重新创建用户库。
